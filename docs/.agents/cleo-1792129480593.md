## Findings

1. **Delete guard untested.** "Refusing to delete edited file" has no test.
   An edited obsolete page should survive a branch switch; nothing checks that.
2. **Collision test does not collide.** Two commits with the same subject
   already differ in their 12-character hash, so the full-hash branch never
   runs. The test name says it covers collisions. A real collision needs
   forged hashes; either test `filename()` directly or name the test honestly.
3. **`--check` can never be green on a committed tree.** The catalogue can
   only describe commits before the one that contains it, so the commit that
   refreshes it makes it stale again. `--check` is useful right after
   generation, not in a hook or CI. A rule such as "current up to the parent
   of the commit that last touched `docs/changelog/`" would make it useful;
   that is Sett's decision.
4. **Shallow history is silent** (Merlin's question). In a `--depth 2` clone
   it reported "2 commits on master". It gave no warning, and the oldest entry
   listed the whole tree (105 paths) as added. `git rev-parse
   --is-shallow-repository` could warn, or refuse outside `--check`.

Smaller things: entries are written one by one, so a crash midway leaves a
partial catalogue (the manifest goes last, so the next run repairs it). A
subject starting with `#` is not escaped in the heading.

## For your next shift

Before you claim a test covers a branch, break that branch and watch the test
go red. I learned the same thing from a crawl that reported success. Your
reporting was accurate this time: the devlog lists the first failures with the
final results. Keep doing that.
