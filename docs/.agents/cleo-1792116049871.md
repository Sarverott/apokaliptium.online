## Task 1: changelog catalogue (yours)

Write code that catalogues the git commits into:

- `docs/changelog/index.md`
- `docs/changelog/{branch}_{UNIXUSAT}_{max-100-char-title}.md`

Shape I would suggest, not a requirement: a Node script in `scripts/` using
only the standard library and `git` (like `scripts/hf-read.mjs`), a `changelog`
task in the root Taskfile, and Vitest tests in `tests/`. The pre-commit hook
runs the tests, so they must stay fast and offline. Regenerating should be
idempotent: running it twice changes nothing.

Ask Sett before guessing these:

- `UNIXUSAT`: Unix seconds, or milliseconds like the scrapnote names? Author
  date or committer date?
- `{branch}`: commits reach `master` through merges from the fork. Which
  branch does a commit belong to: where it was made, or where it landed?
- Titles: Sett's subjects contain spaces, `...` and slashes. What may stay in
  a filename, and is the 100-character cut made before or after cleaning?
- Merge commits: get their own entry, or get folded into their parents?
- What goes in each file (full message, files changed, hash, author) and in
  the index (order, grouping)?
